## 检查发现

1. 早期帧中，多只鸭子会被合并进同一组，部分蓝色结构也属于该组。
2. 中后期帧中，多个鸭子仍共用颜色，同一只鸭子也可能出现多种分组颜色。
3. 增加 K 或提高运动特征权重，仍未得到稳定的一物体一组对应关系。

这说明本次聚类得到的是特征相似的 kernel 集合，不能直接当作物体实例标签。
组颜色固定不代表物体身份可靠。着色还会把原本颜色较暗或被遮挡的 kernel
变成亮色，因此会暴露 RGB 图中不明显的几何；着色面板不等于物体分割真值。

直接基于这些标签加入组间排斥有两种风险：同一物体被拆组后互相推开；
不同物体合组后得不到互斥约束。现阶段不宜据此开始长训练。

## 中心定义与后续实现边界

当前中心为 `c_g(t)=sum(w_i*x_i(t))/sum(w_i)`，其中固定权重
`w_i=opacity_i*前景候选出现次数`，只在同组内求和。
它是对已有 C1 轨迹的几何统计，不是新学习的运动，也不是物理质量中心。

已经单独实现并测试组中心、零均值局部形变、可学习分段线性中心轨迹、
增密/裁剪标签继承，以及跨组有效球重叠软约束。这些模块尚未接入 C1。
Gaussian 尾部正常重叠，软重叠损失不能保证严格无穿透。

下一步应先通过带时间身份的训练帧实例掩码等信息检查并修正 kernel 归属，
保留不确定点为未知；之后才适合比较 C1、C1+中心运动、C1+中心运动+跨组接触。
本次标签绑定当前 checkpoint 的 kernel 顺序，不能直接复制给新的随机初始化。

验证：10 项单元测试通过；72 张拼接图的 GT/C1 区域在候选之间逐像素相同；
原 C1 配置与权重 SHA256 校验一致。检查凭据见同目录 `verification.json`。
